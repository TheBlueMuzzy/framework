# Game UI catalog

Every known, common game screen. **Built** = ready in the kit: import it from `src/ui/kit` and pass words, data and callbacks. **Recipe** = not built yet: build it from the listed parts the first time a game needs it, then add it to the kit as Built (and bump `kit/VERSION`).
**Needs React 18 or newer** (tested on 18.3 and 19; `install-kit` warns if a game's React is older).
**Check the rules:** `node src/ui/kit/check-ui.mjs src/ui --css src` — fails on raw colours / px / fonts in UI code; `--css src` also warns (doesn't fail) about the game's CSS restyling kit parts (a selector naming a `.kit-…` class that sets more than CSS variables): the look belongs in the style file or a kit option.
See any Built screen live: `npm run dev` in `ui-kit/`, then `http://localhost:5180/?screen=<id>&preset=<style>`.

**Rule: non-buttons never look like buttons.** Only things you can press get a filled pill/box with an outline and a drop shadow. Instructions ("Hold to Roll", "Locked 1!") and small info ("Round 1") are `HudText`: plain words in the style's `on-game` colour with a soft `game-shade` halo, no plate. HUD chips (scores, player chips, counters) are flat plates with no shadow. Never use a `Badge`, `Panel` or `Button` just to show words.

## Parts (`?screen=parts`)
- **Layout:** `Screen` (slots `topLeft` `top` `topRight` `bottomLeft` `bottom` `bottomRight` + centre · `dialog` = dims what's under it · `scroll` (0.3.2, `?screen=scrolling`) = the WHOLE screen scrolls when it's taller than the window — drag anywhere, wheel or keys, no scroll bar showing; the centre OPENS in the middle (at the top if it's taller than the window), then its top stays put and it only grows / shrinks DOWN, so a control just tapped stays under the finger; placed again only on a window resize / rotate (0.4.4; 0.4.3 pinned it to the top); the panel's own buttons (Start, Save) scroll with it, never out of reach. Use it instead of a ScrollArea for menus like New Game; safe areas and shadows kept. 0.10.0: the menu frame (below) is the new way — no Screen scroll, the card's ScrollArea body scrolls; `scroll` stays for games that use it. It catches taps on its own empty space, and a stray tap there never closes it (a form would lose its choices; 0.3.4) — Back / Esc do) · `grow="down"` (0.10.0, every kit menu uses it) = the screen never scrolls; the centre card OPENS in the middle, then its top stays put and it only grows / shrinks DOWN (a control just tapped stays under the finger), placed again only on a resize / rotate / fonts loading; it never runs off the bottom (its height limit loses the top gap) — there its ScrollArea body scrolls · `column` (0.12.0) = a phone-shaped game on a wide window: the slots sit in a centred column a phone's width (`--kit-column-w`, default 9:16 of the window's height, at least 22.5rem), the backdrop still covers the whole window; short windows (≤ 30rem tall) use the whole width and the `bottom` slot (a title) moves LEFT of the centre so the centre keeps the height · `swipe={{ up, down, left, right }}` (0.12.0) = a swipe anywhere on the screen (≥ 3rem, mostly one way; mouse / pen by pointer events, a finger by touch events — those still arrive when the browser claims the gesture) calls that direction; a swipe that can scroll what it started on is left to scroll; `useSwipe(ref, swipes)` for any element · `slide` `in` / `out` + `slideEdge` (bottom default / top / left / right) + `onSlideEnd` (0.12.0) = the whole screen slides in from / out to that edge at `motion-normal` (out stays out until removed), `onSlideEnd` once (straight away with reduce motion) — e.g. a menu sliding away to show the game under it · `Panel` · `Stack` (column) · `Row` · `Grid`. Gaps by name: `xs s m l xl`.
- **Controls:** `Button` (primary / secondary / ghost / danger, + `icon` — square, ≥ 44px, glyph at title size, `loading`, `size` — px tall/wide to match a game piece, never below target-min, `compact` — less room each side of the label, so a row of big buttons fits one line on a narrow phone, `sound` — 'tap' default · 'back' · false when the game plays its own sound; 0.27.0: danger is lit like primary — Neon glows it red, `glow-danger` — so − / + read as a pair) · `Toggle` · `Slider` · `Selector` (◀ option ▶) · `Stepper` · `Tabs` · `Carousel` (one item at a time, moves on every `autoSeconds`; LOOPS — past the last the first slides in from the same side, only the two items move; tap / ◀ ▶ / ← → / swipe moves and holds it `pauseSeconds`; page dots; `index` + `onIndexChange` to mark the shown item elsewhere; reduce motion = no slide) · `TextInput` · `RoomCodeInput` · `ListRow` · `Card` (`selected`; 0.27.0: `tone="success"` — owned / done: edge in the style's success green + `depth-success` shadow, same size; `locked` — greyed but readable at 4.5:1, same size, never a button, `aria-disabled`, read out "Locked" / `lockedLabel`; showing or hiding locked things is the game's call) · `Badge` (neutral / primary / danger; 0.31.0: success) · `Avatar` (+ `color` — 0.21.0: initials white on a dark colour, black on a light one; initials in the body font, semibold) · `ProgressBar` · `PullHandle` (0.12.0 — a lever / periscope / cord to DRAG along `direction` down (default) / up / left / right, up to `travel` (share of its own length, default 0.5); let go past `threshold` (share of the travel, 0.6) and it glides to the end (`motion-normal`) and calls `onPull`, short of it it springs back. Its GRIP is a real button named `label` — `grip` = the share of its length you can grab, at the end it's pulled by (default 1 = all; e.g. 0.35 = a periscope's goggles, its long stem hidden behind something isn't pressable): a TAP, Enter / Space or its own arrow key pulls it all the way, so nobody has to drag. `pulled` keeps it at the end; children = its look (the game's picture, unread); `--kit-pull` 0 → 1 on the handle while dragged; `touch-action: none`) · `ScrollArea` (0.10.0: no scroll bar — drag, swipe, wheel, keys still scroll it; its top / bottom edge fades while there's more that way: `data-more-start` / `data-more-end`, fade height `--kit-scroll-fade` 2rem, never more than what's hidden; `data-scrolls` = it really can scroll, and only then keeps swipes to itself) · `Text` (never leaves one word alone on a wrapped last line: CSS text-wrap pretty, plus `noOrphan(sentence)` for game-built sentences).
- **Glue:** `ScreenStack` (`overlay` = over a game with its own UI; only the TOP open screen shows — screens under it are hidden + inert until it closes; a screen opened over another always dims, so there's one dim over the game, 0.2.8–0.2.9; 0.7.0: the FIRST screen over the game's own layer — children, e.g. Settings over a main menu — dims it too (`data-dim`, fades in like a dialog's)) + `screens.push/pop/replace` · `kitScreens` (0.25.0: always added under the game's screens — no need to list them; a pushed name with no screen warns and closes) · `applyStyle` · `applyAccessibility` + `loadSettings` · `fill('Round {n}', { n: 2 })` · `copyText(text, shownElement)` (clipboard, or selects the text where there's none) · `reduceMotion()` / `useCountUp(n)` (numbers that roll up, off with reduce motion) · `useFixedSize()` (0.21.0 — a ref for a card that must keep its size once it's on screen; in dev builds a later growth shows up in the checks as "grows:" — `Card` and `PlayerChip` use it).
- **Control sounds** (0.4.2): the kit never plays audio itself — a game plugs in once with `setControlSound((kind) => playSound(`ui.${kind}`))`. Button / Tabs / clickable ListRow / ◀ ▶ say `tap`, a Toggle says `toggle`, Back / Close ✕ / Resume say `back`; `sound={false}` on a Button whose press has its own game sound. Code: `kit/controls/controlSound.ts`.
- **Keyboard** (0.3.2): on the top open screen (or, with none open, inside the Panel the focus is in — the game's own keys are left alone) ↑ / ↓ jump from control to control in reading order — buttons, pickers, switches, sliders, boxes to type in — never words or anything hidden, inert or disabled; past the last it wraps to the first, and the control scrolls into view in a ScrollArea. ← / → work the focused control: `Selector` / `Stepper` step (also after a click on ◀ ▶), `Toggle` off / on (its sound: toggle.on / toggle.off, 0.4.3; off sounds before it changes, on after it changes, so a Sound switch is heard both ways, 0.4.4), `Tabs` and `Carousel` move. A box you type in keeps all its arrows. No text caret ever shows outside a box you type in (caret-color, for Chrome's caret browsing — F7). Focus ring for keys and pads only (`:focus-visible`), never after a click or tap. Code: `kit/arrowKeys.ts`.
- **`kit-scope`:** wrap kit parts shown outside a Screen — e.g. pinned to a 3D point — in `<div className="kit-scope">`: they get the style's fonts, colours, text size and focus ring, but no layout, background or positioning (and taps are left as they were).
- **Pinned** (`?screen=pinned`) — kit parts stuck to a point in the game world (a chip beside a row on a 3D table). Kit parts are sized in rem, but a pinned piece must scale WITH the table. `PinnedBox` does the sizing and knows nothing about 3D; a tiny adapter in the game (the only file that imports three / R3F) puts it at the point and passes `pixelsPerUnit` (screen pixels one world unit takes up there). Props: `fit={[w, h]}` (world units: fit that box, tighter side wins) · `rem` (world units per rem: every piece with the same rem is the same size; `fit` still shrinks one that would spill) · `anchor` `right` (default: its right-middle on the point) / `center` / `left` · `name` (→ `data-pin`). Hidden until measured, wears `kit-scope`, never catches taps. Also exported: `pinScale()` (the maths). **Layers:** pinned pieces go above the game canvas but below the HUD and kit screens — e.g. drei `zIndexRange={[5, 0]}`, the game's HUD at z-index 10, `ScreenStack overlay` at `--kit-overlay-z` (default 100).
  ```tsx
  // src/components/Pinned.tsx — the game's R3F adapter (the kit never imports three)
  import { Html } from '@react-three/drei'
  import { useThree } from '@react-three/fiber'
  import { Vector3 } from 'three'
  import { PinnedBox, type PinnedBoxProps } from '../ui/kit'
  const a = new Vector3(), b = new Vector3()
  export function Pinned({ position, ...box }: Omit<PinnedBoxProps, 'pixelsPerUnit'> & { position: [number, number, number] }) {
    const camera = useThree((s) => s.camera), size = useThree((s) => s.size) // re-measures when the window resizes
    // screen pixels per world unit at this point: project it and a point one unit to its right
    a.set(...position).project(camera); b.set(position[0] + 1, position[1], position[2]).project(camera)
    const pixelsPerUnit = (Math.abs(b.x - a.x) * size.width) / 2
    return <Html position={position} zIndexRange={[5, 0]} style={{ pointerEvents: 'none' }}><PinnedBox pixelsPerUnit={pixelsPerUnit} {...box} /></Html>
  }
  // style pointerEvents none, NOT the pointerEvents prop — that prop only works in drei's transform mode; without it the label's invisible box eats taps on the 3D scene under it (Roll Better 2026-09-29)
  // use: <Pinned position={[-4, 0, -3.75]} fit={[2.95, 1.15]} rem={0.34} name="me"><PlayerChip size="xs" … /></Pinned>
  ```
- **Hand view** (`?screen=hand`, kit 0.3.0) — `HandView`: a player's hand drawn as a RACK (preset "rack"; a fan comes later) — one SVG, a row of places, or 2 rows if one doesn't fit (shrinks only if 2 rows still don't). It knows nothing about the game: it positions and animates, the game draws. The order of places comes from the table module's rack order (`table/kit/rack.ts`, `GAP` = an empty place). Props: `layout` (from `rackLayout({ room, tileWanted, places, tileMin, gap })`) · `boxWidth` (the places sit in its middle) · `places` (each: `key`, `piece` — the game's own data, leave out for an empty place, `attrs` — data attributes the game's input code finds with `closest()`, e.g. `{ 'data-tray-pos': 3 }`, `held` — lifts + `data-held`, `aimed` / `waiting` — faded / dimmed, `staged`, `origin` `'ghost'` / `'empty'` — its piece is being carried: a faint mark / nothing at home, attributes kept; `data-carried`) · `renderEmpty(spot)` (drawn under EVERY place; a free place shows only this) · `renderPiece(place, spot)` (`spot` = `{ index, x, y, tile }`) · `hidden` (passing the device: only empty looks, no attributes) · `stage` `out` / `gone` / `in` + `motion` `{ shrinkTime, growTime, stagger, overshoot, shrinkEasing?, growEasing? }` (seconds) — the staged pieces shrink away one after another, stay away, grow back in with an overshoot (Web Animations on `[data-refresh-slot]` groups, the svg says `data-refresh-stage`; reduce motion = none; the game runs the clock) · `look` `{ lift 0.08, headroom 0.1, waitingOpacity 0.55, aimedOpacity 0.8, ghostOpacity 0.45 }` (shares of a place) · `className` (added to `kit-hand`) · `label` · `insertAt` + `renderMarker(gap)` · `makeRoomAt` (0.6.0 — see Target feedback). Also exported: `rackPlaceCentre(layout, boxWidth, index)`, `rackLeft`.
  ```tsx
  <HandView layout={layout} boxWidth={column} className="game-tray" label="Seeds" hidden={handoff} stage={refresh?.stage} motion={timings}
    places={order.map((id, i) => id === GAP ? { key: `empty-${i}`, attrs: { 'data-tray-pos': i } }
      : { key: id, piece: id, attrs: { 'data-hand': id, 'data-tray-pos': i }, held: id === selected, waiting: !myTurn, staged: refresh?.slots.includes(i) })}
    renderEmpty={({ x, y, tile }) => <polygon points={hexCorners(x, y, tile / 2)} className="slot" />}
    renderPiece={(place, { x, y, tile }) => <image href={artOf(place.piece)} x={x - tile / 2} y={y - tile / 2} width={tile} height={tile} />} />
  ```
- **Carry styles** (kit 0.5.0, `kit/drag/`) — how a DRAGGED piece looks (the Table referee still says whether it may go there). A style = `{ carried: solid|ghost, origin: solid|ghost|empty, land: settle|solid|fly, back: fly|fade }`; presets `CARRY_PRESETS` A Pick it up (solid · empty) · B Lift, mark home (solid · ghost) · C Aim (ghost · solid; a valid drop = the real piece flies home → target) · D Float (ghost · empty), names in `CARRY_NAMES`; `carryStyle('C', { back: 'fly' })` picks one + overrides. `createCarrier(el, () => feel)` moves ONE element (svg or html) in a layer over the play area by its centre: `start(style, at, size)` (lifts: `liftScale` + a `--bg` shadow) · `move(at)` · `drop(target | null, home)` → Promise `'landed' | 'returned'` (Web Animations; reduce motion = instant) · `cancel()` · `travel(to, seconds, easing?)` (kit 0.6.1 — "AI looks human": an AI's / another player's piece goes home → spot by itself, lifted, then `drop()` as usual). `travellingLook(style, feel)` → how a piece that glides by itself (a board glide) wears the style: `{ opacity, scale, shadow }`, or null for a style that flies the real piece (C); `liftShadowFilter(size, strength)` = the carrier's shadow as a CSS filter. Feel numbers `CarryFeel` (`DEFAULT_CARRY_FEEL`: ghostOpacity 0.45, liftScale 1.12, liftShadow 0.35, liftTime 0.08, landTime 0.14, flyTime 0.22, fadeTime 0.15 — seconds) belong in the game's content/tuning. Home look for a hand: `HandPlace.origin = originWhileCarried(style)`.
  ```ts
  const carry = createCarrier(dragImage, () => tuning.carry)
  carry.start(carryStyle(tuning.styles.draft), pointer, size)   // pointer-down → drag
  carry.move(pointer)                                            // pointer-move
  if (await carry.drop(valid ? hexCentre : null, homeCentre) === 'landed') commitMove()
  ```

- **Target feedback** (kit 0.6.0, `kit/drag/target.ts`) — what the TARGET shows while a piece is carried (carry = what you hold; the referee still decides what's valid; a game picks per drag type). Highlight = the game's own drawing. **Ghost preview** `createPreview(el, () => carryFeel)` → `show(at, size)` (a see-through copy centred on the landing spot, `ghostOpacity`; a new spot just moves it, no flicker) · `hide()`; never catches the pointer. **Insertion marker** `insertionIndex(pointer, placeCentres)` → the gap (0 = before the first … n = after the last) + HandView `insertAt={gap}` `renderMarker={(gap) => <the game's marker at gap.x, gap.y>}`. **Make room** HandView `makeRoomAt={gap}` slides that row's places apart by `look.makeRoom` of a place in all (CSS transition `motion.roomTime`, on each place's inner `.kit-hand-room` group — held lift and stages unaffected); leave it out to slide back. **Tether** `createTether(svgPath, { color?, arrow?, feel? })` → `show(from, to)` · `update(to)` · `hide()` — a line / gentle curve (`tetherBend`) with an arrow head (`arrowSize`), look from `.kit-tether` (var(--primary); `color: 'var(--accent)'` or the game's CSS overrides). **Magnetic snap** `snapTarget(pointer, validSpots, feel.snapRadius * size)` → nearest spot (with its own fields) or null; `carrier.move(pointer, spot && { to: spot, pull: feel.snapPull, radius })` shows the piece pulled toward it (no jump at the edge; no snap = as before; a drop starts from where it shows). Numbers `TargetFeel` (`DEFAULT_TARGET_FEEL`: makeRoom 0.35, roomTime 0.15 s, snapRadius 0.6 of a piece, snapPull 0.5, tetherBend 0.15, arrowSize 12 px) belong in content/tuning. - **Menu frame** (0.10.0, Muzzy 2026-10-13: "the menus and sub menus (including credit) should be the same width/height with internal scroller"): every menu card — Main menu, Pause, Settings, Credits, Mode select, How to play, Lobby, Results, Seat picker, any `Modal` (classes `kit-menu` / `kit-modal` / `kit-wide`, now one size) — is ONE width, `--kit-menu-w` (36rem, never wider than the screen). A yes / no question on top (Confirm, class `kit-ask`) stays narrower: `--kit-ask-w` 28rem. Height = its contents, up to `--kit-menu-max-h` (44rem; desktop windows ≥ 40rem wide and ≥ 30rem tall: `--kit-menu-max-h-wide`, 52rem) and the screen; past that only its ScrollArea body gives up height (header + footer row keep theirs). Layout: `MenuHeader` · body = ONE ScrollArea (never nested) · optional footer row. Opens centred, then grows DOWN (`Screen grow="down"`). The card's own scroll is only a last resort for very short windows (no bar either). `.kit-tall` does nothing any more (it forced a height). A style or the game's tweaks may set the five sizes (`kit/style/tokens.ts` menuSizeTokens).
- **Fonts: three text roles** (0.16.0, like a web page): `font-title` (Text kind display + title), `font-heading` (Text kind heading, card titles, room-code boxes, art buttons' words) and `font-body` (everything else), plus `font-numbers` (scores, timers). Presets set only `font-display`; title and heading follow it unless the game's style.json tweaks set them, so nothing changes until a game picks. **A game's own fonts:** file (+ its licence / readme when the licence asks) in `public/fonts/<folder>/`, listed in `content/ui/fonts.json` — `{ "fonts": [{ "name", "file" (inside public/fonts/), "licence": commercial-ok 🟢 · credit-needed 🟡 · non-commercial 🔴 · unknown 🔴, "licenceNote", "note", "pixelSize" }] }` — credited in content/credits.json, and declared at start-up with `loadGameFonts(fontsJson, import.meta.env.BASE_URL)` next to `applyStyle`. Then a tweak names it: `"font-title": "'Press Start DX', system-ui, sans-serif"` (`fontValue(name)`). Also exported: `kitFonts` (the kit's 7, all SIL OFL 🟡), `licenceLight(licence)`, `firstFontName(value)`, `gameFontFaceCss`. The Dev Kit's **Fonts** tab (0.17.0) picks, compares and saves these. Pixel fonts are crisp only at their `pixelSize` and its whole multiples. Code: `kit/fonts/gameFonts.ts`.
- **Art skins** (0.11.0, `kit/art.css`, `?screen=artmenu` · `?screen=artend`) — the game's OWN pictures in place of the style's look, for a game with an artist (Goops: Muzzy's console art). The style still does the words beside them. Pictures always keep their shape (sized by one side; never stretched). Put the files where the game's build serves them (e.g. `public/art/`, paths in a content JSON) and pass URLs. **Art with words in it:** a picture (img / backdrop / frame) can't load fonts, so its `<text>` falls back to a system font — outline the words first (Goops `scripts/art-prep.mjs`, opentype.js) or leave the words out and let the kit write them.
  - `Button art={{ up, down?, label?, size? }}` — `up` = the picture at rest, `down` = while held (drawn bottom-aligned in the same box, so a shorter pushed-in picture sinks into its base; `data-pressed` while a finger / mouse is down, so it shows on iOS too). `label` `beside` (default) / `below` / `hidden` (picture only, still read out). `size` s / m / l = picture 3 / 4 / 5.5rem wide (l: heading-size words; short windows: pictures at 75%). No pill, outline, glow or shadow; still ≥ 44px. Without `down` the style's press (sink / shrink) stays.
  - `Screen backdrop="…"` (+ `backdropFit` `cover` default / `contain`) — a picture behind the whole screen; covers the dim a screen gets over another.
  - `Panel frame={{ src, slice: [t, r, b, l], scale?, ink? }}` — the panel inside a frame picture, cut nine ways (CSS border-image): corners at their own shape, only the plain strips between them grow with the contents. `slice` = how far in each corner reaches, in the picture's units (an SVG needs `width` + `height` on its `<svg>`); `scale` = rem per picture unit (default 0.0625); short windows (≤ 30rem tall) draw it at 60%. `ink` = the words' colour on the frame's window: `on-surface` (default) / `on-bg` / `on-game`. `frameVariables(frame)` = the CSS variables, for a game's own box.
  - **Art stage** (0.12.0, `kit/artStage.tsx`, `?screen=artstage`) — a whole SCENE from the game's own pictures, laid out exactly as the artist placed them (Goops: Muzzy's console, cut from his full-screen mock-up). `ArtStage size={[w, h]}` (the scene, in the picture's units) `view={[x, y, w, h]}` (the part that shows; default all) `viewShort` (the part shown on short windows ≤ 30rem tall — e.g. just the top half, so what's left can be read and pressed) `label`: fills its box (in a Screen's centre: the whole centre), the view fitted inside, centred, never stretched. `ArtLayer at={[x, y, w, h?]}` (picture units; no h = the picture's shape decides) — layers stack in order (later on top): `src` = a picture (unread; `label` gives it a name), `text={size}` = words sized in picture units so they grow with the art (never below 0.625rem, one line; `tone` normal = on-game / primary / accent / muted, `align` start / center / end), or any kit part as children (a `PullHandle`, a `LevelMeter`). `off` = drawn switched off: darkened, can't be pressed or focused (inert), read out as unavailable — for a part that does nothing yet; `dim` = darkened but still working (the rest of a machine while a lever is pulled). Placed with a grid + margins (shares of the scene's width), never absolute positioning. Words that were drawn in the art: outline them or strip them and write them with a `text` layer. 0.13.0: `blink` `fast` / `slow` = a lamp asking for attention (on / off in steps; put its "off" picture in a layer under it; not when `off`) · `shake={count}` = one small "no" wobble each time the count changes (a wrong press).
  - **Snap control** (0.13.0, `kit/controls/SnapControl.tsx`, `?screen=snap`) — `SnapControl` = a knob moved between fixed stops by DRAG or TAP (Goops: the console's repair sliders and dial; v1 lost ~80 commits to fiddly touch here). `kind="slide"` (default): the box is the track (the game's art under it), `stops` evenly spaced (stop 0 = left / top), `axis` x / y, `knob` = the knob's share of the track's length. `kind="turn"`: a dial, `angles` = its stops in degrees clockwise from up; it always turns the short way round. `value` = the stop index it shows, `onChange(index)` = where the player moved it (the game decides what's right; refuse = keep `value`, it goes back). Drag: the knob follows from where it IS (never jumps to the finger) and settles at the nearest stop on letting go; a dial turns by how far the finger goes round its centre, and the middle 20% of it doesn't turn it. Tap (moved < 0.5rem): a slide goes to the stop nearest the tap (on the knob: one step toward that side), a dial steps clockwise. A press that moved is a drag, never also a tap. Keys: arrows, Home / End, Enter / Space = a tap. Read out as a `slider` (`valueText`). Hit area = the whole box, at least target-min both ways, centred (a thin track still grabs at 44px). Live position on it as `--kit-snap` (slide 0 → 1, turn degrees). children = the knob's picture.
  - `Button art size="fill"` (0.13.0) — a picture button drawn into a scene: the picture is as wide as its ArtLayer spot (pair with `label: 'hidden'`), still ≥ 44px, centred.
  - `TitleArt src alt size` (0.12.0) — the game's logo picture on its own: m = the main menu's 7rem tall, s = 3.5rem (a bottom row / corner; short windows 2.75rem).
  - Blocks pass them through: `MainMenu titleArt` (logo picture; `title` stays its name) `backdrop`, `items[].art`; `Victory` / `GameOver` `frame`, `backdrop`, `art={{ continue }}` / `art={{ retry, quit }}`.
- **Menu header** (`MenuHeader`, 0.10.0): `<MenuHeader title="Settings" onBack={close} backLabel="Back" action={<Button>Start</Button>} />` → one row: a square ‹ button on the LEFT (only with `onBack`; read out as `backLabel`, default "Back"; sounds like a Back), the title (a string → title text; or any element), `action` on the right.
