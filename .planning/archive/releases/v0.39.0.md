# v0.39.0

## Highlights
A lean, measured framework. Every module now has a game that really uses it, parts no game called were archived (the whole framework is about 29% lighter), and one recipe says how a part moves from a game into the framework and back. Modules only one game uses are frozen — bug fixes only — until a second game needs them.

## Breaking
- Emotes are archived (git tag `archive/emotes-0.4.2`): the emotes module, the UI kit's emote parts (UI kit 0.40.0) and bot banter (AI 0.9.0) are gone. A game that used them stays on its old copies or drops them — `install-module.mjs` prints the steps.
- Saves 0.8.0 keeps only what Glyphtender calls: save codes, link codes, the leaderboard and replays are removed (git tag `archive/saves-0.7.0`) — the update deletes those files from `src/saves/`.
- UI kit 0.41.0: `WhatsNew` is archived (git tag `archive/whats-new`) — the update removes `blocks/whatsNew.ts`.
- The starter (`starters/turn-based`) no longer carries module copies: after copying it, run `npm install`, then `npm run install-modules` — every module arrives fresh.

## New
- The module recipe (`.planning/design/module-recipe.md`): what counts as a module, the way out of a game, the way in, and what proves each step.
- The framework README's module table says who proved each module, which games use it today, and which are frozen.
- Screenshot runs shoot only the styles games use on routine runs; all seven before a UI kit release.
- BMUZ (shared by every project, not a module): one file per hook rule with its reason and test; a firing log of every rule; fewer false alarms; a new rule or module must say what it replaces; the monthly checkup proposes rules to cut.

## Fixed
- BMUZ's own script tests: the removal-pass test no longer expects a protected safety guard to be proposed for cutting.
