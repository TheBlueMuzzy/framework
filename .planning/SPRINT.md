- Task 1 (Claude): standards are whole-game numbers (console −24/−23 LUFS, phone −18/−16, ceiling −1 dBTP, ±2 LU); there's no standard per category — studios level every file to one reference and mix in the engine. So **every folder defaults to −18** and the mix stays in the buses (ui −8, music −8, ambience −10 already). Tolerance 3 dB (a single click wobbles more than a whole game's average). Short sounds use Goops' active loudness, long ones real LUFS (BS.1770, written in JS — testable with made-up samples, no ffmpeg needed).
- Task 2 (Claude): the matcher lives in **audio/kit/loudness.mjs** (not audio/scripts/): only kit/ is copied into a game (→ src/audio/), and the check:framework part (kit/conformance.mjs) and audio-check need it there — the same reason ui-kit's check-ui.mjs sits in its kit/. It has its own 4-line findFfmpeg (same rule as the Dev Kit drop: FFMPEG_PATH, else ffmpeg) because the audio module and the Dev Kit install separately. Surprise: the usual "RBJ" filter recipe gives K-weighting 0.25 dB off; the libebur128 recipe matches BS.1770 exactly (a full-scale 1 kHz sine = −3.01 LUFS, tested). Surprise 2: limiting can't be re-applied on every --fix (a spiky file would be shaved 3.5 dB more each run) — a file whose original is already kept in audio-originals/ gets no more limiting, and if it's still quiet it's "as loud as its spikes allow", not flagged.
- Task 3 (Claude): **how the Dev Kit gets the matcher — it loads the game's own src/audio/loudness.mjs when a file is dropped** (a runtime import from the dev server). One copy, owned by the audio module, so the drop, audio:check and check:framework can never disagree; no copy to keep in sync. A game with an audio module older than 0.4.0 still gets its MP3, just not levelled, and the Sound tab says so. Rejected: a second copy in the Dev Kit (two copies drift), importing ../../audio/ (that path doesn't exist in a game). The dropped file is kept in **audio-originals/<folder>/** (outside public/ — anything in public/ ships to every player, and the service worker may cache it), which is also how audio:check knows a file was levelled once already (no second round of limiting). The answer has a new `loudness` line ("levelled to -18.0 dB (was -37.7; target -18)"), shown in the Sound tab's status.
- Task 4 (Claude): **audio/kit/audio-check.mjs** (in kit/ like the matcher, so it ships to src/audio/); install-audio now adds `"audio:check": "node src/audio/audio-check.mjs"` to a game's package.json when missing (the Dev Kit installer's check:framework bookkeeping, same shape). Originals go to **audio-originals/<same path>** at the game root, not public/audio/_originals/: anything under public/ is copied into every build and shipped to players. Never overwritten — the first original kept stays; nothing is ever deleted; writes only inside public/audio/ and audio-originals/ (links skipped, real paths checked). `--fix` re-measures each file it changed and says if one is still off.
- Task 5 (Claude): a third Audio check in kit/conformance.mjs, "every sound is as loud as the others and starts on time" — `(t.warn ?? t.fail)` like F103/F104, each off file named with its problem, the fix `npm run audio:check -- --fix`. It runs under `--static` too (it reads files, no browser), so install-module's own check runs it. No ffmpeg → a skip with the install line; no sounds yet → a skip.

The template's loudness block has _help / _labels / _ranges and its own "File loudness (audio:check)" section; a test keeps it equal to loudness.mjs's defaults. content/audio.json's validator (kit/config.ts) is unchanged: the engine never uses "loudness" and the validator already ignores top-level keys it doesn't read — loudness.mjs validates the block itself (a bad value is named and the default used). ~/.claude/skills/audio-setup/SKILL.md Step 6 now points at `npm run audio:check` (outside the repo, not committed here).
