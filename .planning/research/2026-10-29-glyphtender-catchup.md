## Framework / installer problems found
- install-module.mjs: its usage line + `CHECK_ID` list name 10 modules but not `lint` — lint only installs if it is picked up as a "new module" (kit/VERSION + bmuz folders). (to verify at step 3)
- **No per-module CHANGELOG / upgrade notes.** The brief (and BMUZ habit) expects "the module CHANGELOG's upgrade steps"; the framework has only the root `CHANGELOG.md` (by framework version, prose) + a long version line at the top of each README. A game jumping ui-kit 0.20 → 0.38 has to read 18 framework releases to find what it must do by hand. Suggest: each module's README gets a short "Upgrading from older versions" list (version → hand step), or the installer prints "since your version: …" steps by reading a `kit/UPGRADES.json`.
- **Table dry run says "already up to date" while the game's stamp says 0.8.0 and the framework is 0.8.2** (0.8.1/0.8.2 only changed the installer). Fine for the code, but the game keeps reporting 0.8.0 — confusing in the planner / STATE versions list. → Verified: the real install DOES rewrite VERSION to 0.8.2, only the dry run's wording misleads. Minor: dry run could say "code unchanged, stamp 0.8.0 → 0.8.2".
- **Crashes' local server port 1995 is already Glyphtender's `online` e2e wrangler port** (`check-all.mjs`: `online … 5404 1995`). The crashes README says "port 1995 locally". Running `crashes:dev` during a check:full would break the online check. Suggest: the crashes installer reads the game's other wrangler ports / check-all ports and picks a free one, or uses a less common default.
- Lint dry run flags the rules engine's refusal reasons (`src/engine/draft.ts`, `refresh.ts`, `rules.ts`, `turn.ts`) as player words, although the lint README says "what a rules `check` returns (the Table's refusal reasons)" is never flagged — confirmed: `lint/kit/rules.mjs:169` only exempts a function named exactly `check`; Glyphtender's rules split it into `checkFor` / `checkDraft` / `checkAction` / refresh + turn helpers, so ~8 of its finds are refusal reasons. Suggest: exempt any function whose name starts with `check` and returns `string | null`, or any function reached from the Rules object's `check`.
- **Audio loudness check ignores the game's own `volumeDb` mix.** It measures the raw file, and `--fix` evens the files — but a game that already balanced by ear with per-sound `volumeDb` (Glyphtender) gets its approved mix changed silently. Suggest: measure heard loudness (file + volumeDb), or have `--fix` move the difference into volumeDb so what the player hears stays the same; at least print "this changes how loud X sounds in game by N dB".
- **Audio update turns check:framework red with no warning in the update notes** (new promise in 0.4.0). The installer's output does say the fix command — good — but the README's version line should say "a game updating from < 0.4.0: run audio:check --fix, then listen".
- `audio-originals/` (made by `audio:check --fix`): README says it's outside public/ but not whether to commit it or gitignore it. Suggest the installer adds it to .gitignore (or says "commit it").
- **Install order: a module's checks can need a newer Dev Kit runner, with no version check.** ai 0.8.3's `conformance.mjs` calls `t.warn`, which the Dev Kit 0.20 runner doesn't have → "its checks ran ✗ TypeError: t.warn is not a function — A framework bug, or the game is missing something". install-module should either refuse/flag ("ai 0.8.3 needs Dev Kit ≥ 0.2x — update devkit first") or the brief's "smallest risk first" order should be **devkit first** (it's the runner every other module's checks use). Suggest each module's package.json declares `"bmuz": { "needs": { "devkit": "0.26.0" } }` and install-module checks it.
- **ai: an old personality field changed meaning.** `chattiness` existed (unused) in games from before ai 0.5.0; now > 0 = "must have banter lines + botBanter + emotes". A game updating gets 2 red promises for a feature it never chose. Suggest: the installer, on a first update past 0.5.0 with no `banter` in en.json, asks "your bots have chattiness but no lines — set them to 0, or add banter?" instead of failing.
- **rooms: `OnlineRoom` gained required fields with no note** — a game that builds a stand-in room (Dev Kit previews, tests) fails `tsc` after the update. Suggest: export a `fakeOnlineRoom(overrides)` helper from the kit (so previews never go stale), or list type changes in the installer's output.
- **check-all refuses every e2e while any fast check is red** — sensible normally, but during a module update a known-red framework row (e.g. "Rejoin match not wired yet") blocks the area e2e that would prove the update didn't break play. Suggest `check:full -- --allow-red framework` or a way to mark a promise as "known gap" (like Glyphtender's F89 half pause).
- **UI kit added scroll-driven animations (card foot fade) that any "wait until animations finish" test helper sees as running forever** (Glyphtender's shots.mjs: 16 lobby shots timed out). Suggest: the kit exports a `settled(page)` / `isSettling(animation)` helper for games' e2e, and the changelog notes "scroll-driven animations: filter `a.timeline !== document.timeline`".
- **UI kit size changes aren't called out.** 0.20 → 0.38 made player chips / seat rows taller (padding rule) — fine for the kit's own checks but it moved Glyphtender's end-screen board and pushed its lobby's 4th seat off a short screen. Suggest: changelog lines tagged "LOOK CHANGE" so a game knows to re-shoot and show Muzzy.
- **BUG — lint installer breaks eslint.config.js when the config list has a `//` comment** (`lint/scripts/install-lint.mjs:99-101`). It strips comments to find "the list's last real code", measures that length, then uses it as an index into the ORIGINAL text. Glyphtender's globalIgnores line has a trailing comment, so the index lands ~130 characters early and the comma goes inside a word: `re,actRefresh.configs.vite` → "ReferenceError: re is not defined", the game's lint (and check:fast) dead. install-module did catch it ("the game's own lint fails") but left the file broken. Fix: compute the position on the original text (e.g. find the last non-comment, non-space character by walking back from the end, skipping `//…` to end of line), and add an installer test with a trailing-comment config. Likely hits any game with a commented config list.
- npm prints `npm warn Unknown project config "min-release-age"` on every npm command since install-module added `.npmrc` (this PC's npm is older than 11.10). Harmless but noisy in every check log — the install-module comment says "older npm ignores the line, no harm"; it does warn. Suggest: only add it when `npm --version` ≥ 11.10, or note the warning.
