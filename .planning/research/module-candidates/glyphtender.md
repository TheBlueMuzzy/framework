## D. Surprises

- **Goops is further ahead on the tutorial than Glyphtender.** Glyphtender's tutorial is woven into its rules; Goops built a separate lesson player (lessons are JSON files) and wrote in its code that it's meant to become a framework brick. Its `Spotlight.tsx` also says the kit's Callout should learn several cut-outs.
- **Goops has another part written to be lifted:** `src/ladder/` ("every rank gate in one file", 132 lines + README: "self-contained … so it can move into the framework as a module"). That's the other report's to judge, but it's the same kind of find.
- **Both games built half of the same thing for phones.** Glyphtender: full screen + upright lock. Goops: upright lock + "Turn your phone upright" card. Neither has both.
- **Goops writes the same "follow a Settings row" code three times** — a sign the UI kit is missing one small helper.
- **Goops has no Lint brick** (`src/lint` is missing; its `eslint.config.js` has only the standard rules). So "values live in `content/`, no React state every frame" isn't checked by a machine in Goops, only by judgement. Not frozen, so not in B, but it's the module Goops lacks that matters most day to day.
- **Saves and Crashes would come unfrozen** if Goops takes them — the only two frozen bricks a second game wants.
- A stale comment: `e2e/shots.mjs:3` says a phone on its side shows "Turn your phone upright" — Glyphtender has no such card (`fullscreen.ts:40-41` says a sideways phone "just looks sideways"). Only Goops has the card.
