# Saves — upgrade notes

Hand steps a game does when it updates this module, newest first. `install-module.mjs` prints the ones between the game's version and the new one.
Format: `- <version>: <step>` (LOOK CHANGE = sizes or looks change: re-take the game's screenshots and show Muzzy before re-recording them) · `Needs Dev Kit: <version>` = the install is refused on an older Dev Kit.

- 0.9.0: BREAKING for a game whose save keeps moves (a `moves` or `record.moves` list — e.g. the starter's match run; Glyphtender's and Goops' saves hold none today, so for them this is nothing): its golden-save test now FAILS ("it holds moves but nothing replays them") until the game hands in its replay (F190). By hand, in `tests/saves/saves.test.ts`: (1) on that save's line in RUNS (or SAVES) add `replay: <the call Continue makes to rebuild the game from the saved data>` — it must throw when a move doesn't fit today's rules. The starter's: `import { replay } from '../../src/table/core'` + `import { ticTacToe } from '../../src/game/rules'` → `{ run: matchRun, sample, replay: (run: MatchRun) => replay(ticTacToe, run.record) }`. (2) Pass it through: `RUNS.map(({ run, sample, replay }) => ({ save: run.save, sample, replay }))`, `for (const { save, sample, replay } of everySave)`, and `checkGoldenSave(save, copy, replay)`. Then run the save test: a golden save whose moves no longer fit now fails here, naming the move (fix its moves or add an upgrade step) — before, it failed only on a player's Continue. Saves without moves (settings, progress — Goops') need nothing.
