# Version — upgrade notes

Hand steps a game does when it updates this module, newest first. `install-module.mjs` prints the ones between the game's version and the new one.
Format: `- <version>: <step>` (LOOK CHANGE = sizes or looks change: re-take the game's screenshots and show Muzzy before re-recording them) · `Needs Dev Kit: <version>` = the install is refused on an older Dev Kit.

- 0.3.0: Nothing to change in the game's code. A game with its own before/after screenshot check: bring e2e/shots.mjs to template 2 (it adds `?freeze-version` to every page, so the menu and Settings show v0.0.0.0 and stop going red after each /save); a game that held the label still by hand (Glyphtender's `shownVersion` in src/game/freeze.ts) can drop that and pass `versionLabel` again.
- 0.2.0: A game with an offline cache (vite-plugin-pwa): in src/main.tsx swap its own update line for the starter — `registerSW({ immediate: true })` (Glyphtender, Roll Better) or Goops' block (`ourWorker` / `hadWorker` / `swap` + the controllerchange listener) becomes `startUpdates(registerSW)` with `import { startUpdates } from './version'` (keep `import { registerSW } from 'virtual:pwa-register'`; a worker named in vite.config.ts VitePWA "filename" → `startUpdates(registerSW, { worker: 'goops-sw.js' })`). Needs vite-plugin-pwa 1.3.0+ (Roll Better is on 1.2.0: `npm i -D vite-plugin-pwa@^1.3.0` first — older ones ignore onNeedReload and reload by themselves). Then its e2e/sw-update.mjs may call `checkUpdateArrives(page, { url, next, publish, worker })` from `../src/version/e2e.mjs` for its first-visit + returning-player checks. A game without an offline cache: nothing to do.
